## 2026-10-25 二次勘误:标准距离 = 400m 倍数(与距离档是两条独立的轴)

**问题(用户纠正)**:上一轮把 `is_basis_distance` 当成「标准距离 = 中距离/长距离」,
映射进了 `distanceTypes`。**这是错的**。游戏内定义:

> 標準距離(根幹距離)= 赛程全长为 **400 米的整数倍** 的赛事。
> 1 = 标准距离;0 = 非标准距离。与「短距离/英里/中距离/长距离」这个距离档**完全无关**。

对照数据可见两条轴互相穿插:

| 距离 | 距离档(distance_type) | 400 倍数? | 标准距离◎ | 非标准距离◎ |
|---|---|---|---|---|
| 1200 | 短距离 | ✅ | 生效 | 不生效 |
| 1600 | 英里 | ✅ | **生效** | 不生效 |
| 1800 | 英里 | ❌ | 不生效 | **生效** |
| 2000 | 中距离 | ✅ | 生效 | 不生效 |
| 2400 | 中距离 | ✅ | 生效 | 不生效 |
| 2500 | 长距离 | ❌ | **不生效** | **生效** |

上一轮的错误实现导致:1600/1200(英里·短距离的 400 倍数)反而**不生效**,
2500(长距离非倍数)反而**生效** —— 恰好全反。

**修正**:
- 数据侧 `is_basis_distance` 不再写进 `distanceTypes`,改为独立布尔 `restriction.basisDistance`
  (true = 400 倍数,false = 非 400 倍数;支持 `!=`)。受影响 12 处 / 6 条常时绿技能
  (标准距离◎○× + 非标准距离◎○×)。
- 引擎 `clauseSatisfied` 判定 `course.distance % 400 === 0`。
- UI 赛道摘要直接显示「标准距离/非标准距离 + 距离」,技能限制文案写「标准距离(400m倍数)」。
- 测试改为按距离选赛道:1600/2400 生效、1800/2500 不生效(四种组合都覆盖)。

**为什么之前会错**:上一轮是「按技能名推测语义」(标准距离像中长距离),没有去读定义。
这次的规矩:**每个 token 的语义必须能指到一份定义或能自证的等价物**,否则不做映射:

| token | 真实含义 | 判定依据 |
|---|---|---|
| `distance_type` | 1 短距离(≤1400)/2 英里(1500~1800)/3 中距离(1900~2400)/4 长距离(≥2500) | 解包 `course_data.distanceType` 字段本身(实测区间吻合) |
| `is_basis_distance` | 赛程全长 400 米整数倍 | BWIKI 技能页「触发条件:赛程全长为400倍数」+ 英文 wiki「multiples of 400m」 |
| `ground_type` | 1 草地 / 2 泥地 | 技能名对齐(泥地直线◎ = ground_type==2) |
| `ground_condition` | 1 良 / 2 稍重 / 3 重 / 4 不良(枚举存 0~3) | 良场地◎ = ground_condition==1 |
| `rotation` | 1 右回り(顺时针)/ 2 左回り(逆时针) | 顺时针◎ = rotation==1、逆时针◎ = rotation==2 |
| `weather` | 1 晴 / 2 阴 / 3 雨 / 4 雪 | 晴天◎=1、阴天◎=2、雨天◎=3、雪天◎=4 |
| `season` | 1 春 / 2 夏 / 3 秋 / 4 冬 / 5 樱花 | 春季优俊少女◎=[1,5]、夏季=[2]、秋季=[3]、冬季=[4] |
| `running_style` | 1 逃 / 2 先 / 3 差 / 4 追 | 与技能名对齐;大逃并入逃 |
| `motivation` | 1 绝不调 ~ 5 绝好调 | 技能名对齐(b2 分支多为「绝好调以外」) |
| `is_abroad` | 1 海外赛场 | 隆尚/圣安妮塔公园/德尔马 = 海外(102xx) |
| `base_speed/stamina/power/guts/wiz` | 面板五维 | 拉普拉斯妖(1)/(2) 按 速度/智力 分流 |
| `course_distance` | 赛程全长(米) | 直接比较 |
| `is_tight_track` | 小回り赛场(札幌/函馆/福岛/小仓/川崎/船桥) | 触发条文明文列出 6 场 ⇒ 文本侧已落成 `venues` |

## 2026-10-25 触发代码严格执行(标准距离类遗漏 + 分支 OR 语义勘误)

**问题(用户指出)**:「标准距离」这种要判断赛道长度的绿技能没有生效;要求排查同类问题,
技能发动条件按触发代码严格执行。

**排查方法**:把 213 条常时绿技能与全库 1906 条解包技能的条件字符串逐 token 统计,
对照 clean-skills 的解析分支,找出**被当成「环境前提视为满足」而当掉的真实条件**。

**发现 3 类问题**:

1. **`is_basis_distance`(12 处)被当环境前提** —— 它就是「标准距离◎/非标准距离◎」的判定。
   ⚠ **本条当时的映射(标准→中/长距离)是错的,已由上方「二次勘误」推翻**:
   正确含义是「赛程全长为 400 米整数倍」,现为独立字段 `basisDistance`。
2. **`base_speed/stamina/power/guts/wiz`(116 处)、`motivation`(19 处)、`is_abroad`(5 处)同样被当掉**。
   这三类在我们的模型里都能判定(面板五维、干劲选择器、赛道是否海外),已全部改为装配限制:
   - `base_*` → `statsAtLeast`(>=,含)/ `statsBelow`(<,不含),取**面板值**(不含绿技能与干劲);
   - `motivation` → `motivations`(1绝不调~5绝好调,支持 ==/>=/<=);
   - `is_abroad` → `abroad`(隆尚/圣安妮塔公园/德尔马 = 海外,tools/make-courses.ts 打 `overseas` 标记)。
   典型效果:「拉普拉斯妖(1)」需要 速度≥1200 且 智力≥1200(+100 速度),「(2)」需要 智力<1200(+80);
   此前两条无条件生效,会同时计入。
3. **分支语义错**:`@` 变体与 `condition_1/condition_2` 是「或」,但输出时被压成一层**并集**。
   当某支不限某字段时,并集会把它当成「受限」:如 100281 一支限 `distance_type==1`、另一支不限,
   被压成「限短距离」,技能在英里/中距离上整场不生效。全库 **777 条有多变体,其中 401 条各支限制字段不同**,
   即约 400 条技能受此影响。
   已改为 **DNF 子句**:每支单独成一条子句,输出 `restriction.anyOf = [子句...]`(任一满足即生效);
   单字段差异的分支化简回扁平结构((A∧X)∨(A∧Y) ≡ A∧(X∨Y)),被支配的子句剔除。
   最终只有 **10 条**真正异构的技能保留 `anyOf`(如「爱的澎湃♡(2)」= 国内草地 or 海外泥地)。

**顺带修正**:同变体内同字段多次出现应按「与」取交集(如 `ground_condition>=2&ground_condition<=3`),
早期实现是累加成并集;`distance_type!=N` 与 `is_basis_distance` 同时出现也做交集。
文本侧「条件限制」由并集改为**只补空缺字段**(触发代码为准),避免把「代码限先行」放大成「先行/差行皆可」。

**实测(CDP 无头驱动,界面实际值)**:

| 赛道 | 标准距离◎ | 非标准距离◎ |
|---|---|---|
| 中山 草2500(长) | ⚠ 旧数据(错,应为不生效) | ⚠ 旧数据(错,应生效) |
| 东京 草2400(中) | 常时 **+0.11 马身** | 不生效 |
| 中山 草1200(短) | 不生效 | 常时 +0.00 |
| 东京 草1600(英里) | 不生效 | 常时 +0.00 |

(短距离上耐力+60 不触温存,故收益显示 0.00,属正常)

**测试**:114 例全绿(新增 标准距离/非标准距离、面板属性分流、干劲、海外、anyOf 分支语义),
校准双锚未漂移(116.366 / 116.724)。

## 2026-10-25 环境条件核实(场地状态 / 天气 / 季节)+ 回转方向勘误

**问题**:场地状态、天气、季节到底影响什么?引擎的耐力需求与速度是否受其影响?

**方法**:读解包源码 `RaceSolver.ts` / `HpPolicy.ts` / `RaceParameters.ts`(已入库 data/raw),
并在 `data/raw/614tools-worker.js` 全文检索 `ground` / `weather` / `season` 关键字;再用无头浏览器(CDP)
改配置实际观测输出。

**结论(逐项)**:

| 环境项 | 速度 / 加速度 | 体力消耗 | 体力上限 | 技能 |
|---|---|---|---|---|
| 场地状态(良/稍重/重/不良) | **不影响**(RaceSolver 无该参数) | **影响**:系数 草[1.0,1.0,1.02,1.02] / 泥[1.0,1.0,1.01,1.02] | 不影响 | `ground_condition` 装配条件 |
| 天气(晴/阴/雨/雪) | 不影响 | 不影响 | 不影响 | `weather==N` 条件 |
| 季节(春/夏/秋/冬/樱花) | 不影响 | 不影响 | 不影响 | `season==N` 条件 |

- 614tools worker 里连 `ground` 都没有(其模型不含场地状态系数),故天气/季节在两套实现中同样只作技能条件。
- 游戏内「天気」与「馬場」是两个独立选项,**雨雪不会自动把马场变重**,本工具也不做联动。

**界面实测(CDP 真实时间驱动,东京草2400 默认配置 2200/1600/1700/1200/1800 先行 S/A 绝好调)**:

- 场地 良 / 稍重 → 完赛 116.72s、耐力判定「余量充足 +44HP(到达度 101.3%)」
- 场地 重 / 不良 → 完赛 **仍 116.72s**、耐力判定「无余量 −24HP(到达度 99.3%)」
  → 印证「只改体力消耗,不改速度」:完赛时间不变而耐力需求上升 2%
- 晴天◎(速度绿 +20):天气 晴 → 常时 +0.03 马身;天气 阴 → **不生效**、收益 —

## 2026-10-24 耐力判定集成(参考 614tools 耐力计算器)

- 参考:614tools「耐力计算器」(Gorillagame 汉化)的温存判定口径与回体/减益档位输入。
- 本工具实现(利用已有逐帧模拟,不引入采样):
  - 引擎新增体力探针模式 `simulate(course, runner, { ignoreExhaustion: true })`:
    体力可降至负、不温存,用于求"不温存跑完全程所需 HP"= maxHp − min(hp)
  - 汇总条新增**耐力判定**:所需 HP ×1.04(温存判定余量)×1.05(默认安全余量)= 回避线;
    余量 = maxHp − 回避线;到达度 = maxHp/回避线;
    结论三档:≥100% 余量充足 / 实际能跑完但 <100% 无余量 / 会温存=耐力不足(探针 min(hp)<0 ⇔ 实际模拟必温存,两者轨迹在 hp>0 区间一致,判定严格等价)
  - 配置面板新增**耐力试算**:回体 7 档(0.35/0.5/1.5/3.5/5.5/7.5/9.5%)+ 减益 4 档(0.5/1/2/3%),
    每档数量×发动位置(赛程 10/25/40%),合成 heal 技能注入模拟(负 heal=扣除,引擎已支持);
    发动位置与消融表联动展示
- 实测:东京2400 耐1600=余量充足+5HP(100.2%);耐800=不足−420HP(87.7%,归零@2335);
  耐800+回体5.5%×2@25%=无余量−61HP(98.0%),归零消失、完赛 116.72→116.54s ✓
- 口径备注(与 614tools 的差异):它用 256 确定性采样 + 1/15s 步长;本工具用逐帧确定性期望,
  回体→末脚体力预算重算的耦合(回体让跑得更快、总消耗上升)自然包含在探针里。
  回复受上限截断(min(maxHp, hp+回复))与游戏一致。
- 勘误(2026-10-24,用户指出):试算面板改为**仅减益**——回体通过技能选择实现
  (解包 heal 技能 107 条国服已实装,发动条件比固定百分比位置更真实);
