# 赛马娘国服赛道模拟工具 — 最终方案

> 定稿日期:2026-10-24。本方案为唯一有效版本,已合并此前可行性分析与实施方案的全部结论。

## 1. 项目定义与范围

**一句话**:开源的赛马娘国服网页版赛道模拟器——配置属性/跑法/赛道/技能后,直观展示**技能发动位置、全程速度与剩余体力曲线、每个技能的马身收益**。

**v0.1 范围**:

- 单马确定性期望模型,30fps(1/30s 步长)帧级积分
- **技能全量**(国服现有技能,进化技能除外),按三层精度处理(见 §4)
- **赛道全量**:17 赛场,含弯道区间、坡度区间、阶段分界
- 三大视图:赛道条 + 速度/体力双曲线 + 消融马身收益表

**v0.1 明确不做**(仅展示期望数值或后补):多马阻挡/包围、焦躁、追比、取位争夺、下坡加速模式、蒙特卡洛、进化技能、冷却计时器(以"每技能单次发动"模型覆盖绝大多数技能)。此边界与 614tools 现行版本一致。

## 4. 模拟引擎设计

**帧循环**:

```
for frame in 0..finish:
    phase = getPhase(x)                       # 序盘/中盘/终盘/最终冲刺
    targetSpeed = baseSpeed(phase, 跑法, 适性, 干劲, 坡度(x))
                + Σ(激活中的速度类技能效果 × 智力乘算)
    v 以受限加速度趋近 targetSpeed              # 起步 +24 m/s² 至 85% 基准速度等
    hp -= 20.0 × 状态系数 × (v − 基准速度 + 12.0)² / 144.0 × 场地系数
    if hp ≤ 0: 温存模式(目标速度降级)
    判定未发动技能的发动条件 → 激活
    x += v·dt; 记录 {t, x, v, hp}
```

**技能效果模型**:四类效果(目标速度↑ / 加速度↑ / 即时速度↑ / 末脚延展)+ 回体 + 绿技能前提值;固有/レア技能的智力乘算(智力补正按档位累计,公式取自 614tools 页脚,记入 docs/formulas.md)。**马身 = 米差 / 2.5**。

**发动条件引擎(三层精度,24 种条件全量覆盖)**:

1. **精确层**(阶段/弯道/坡道/距离/时间类,占绝大多数):静态条件预解析为赛道上的**可发动区间**(借鉴 uma-skill-tools ConditionParser 思路),运行时逐帧精确判定;可发动区间同时用于 UI 展示
2. **近似层**(依赖他马的条件:序位类、累积时间类、被阻挡类):按 614tools/uma-skill-tools 同款假设——序位类视为满足、累积时间类按期望时刻发动;**UI 打"近似"角标**
3. **不支持层**(极少数):显式标注"暂不支持",不静默算错

冷却以"每技能单次发动"模型覆盖(614tools 同款做法)。

## 5. 数据方案

**获取(一次性,不上持续爬虫管线)**:

- **技能**:BWIKI 技能速查表的结构化数据(1500+ 条)服务端渲染在页面隐藏 div(`jn-json-part`)中——一次性脚本抓取解析(分 4 页,EdgeOne 退避 + 人工导出兜底);配人工维护的条件文本→枚举映射表(`tools/condition-map.json`),异常字段进复核清单
- **赛道**:17 赛场全量(弯道/坡度/阶段分界)以开源解包数据集为主源,BWIKI 坡道页人工核对;国服特有差异靠 override 层修正
- **抽样校验**:随机 50 技能 + 10 赛道与 BWIKI 人工比对,错漏进复核清单

**数据 schema(要点)**:

```json
{
  "id": "...", "名": "...", "稀有度": "通常|レア|固有Lv.x",
  "效果": [{"类型": "目标速度|加速度|即时速度|末脚|回体", "数值": 0.15}],
  "持续时间": 3.0,
  "发动条件": {"类型": "弯道最快", "参数": null, "基准": "起步|中盘|终盘|最终盘"},
  "条件限制": {"距离": "中距离", "跑法": "先行"},
  "受智力加成": true,
  "精度层级": "精确|近似|不支持"
}
```

**更新策略(自 v0.1 起)**:

- 一次性抓取脚本保留在仓库(`tools/scrape-once.ts`),随时可手动重跑
- 后续新技能走**手动更新**:照 schema 手写 JSON 条目提 PR,约 30min~1h/月;CI 的 zod 校验兜住手误(字段缺失/单位错误/枚举拼错直接红灯)
- 预留 `data/overrides.json` 补丁层:国服与解包数据的单点数值差异,改一处即生效,不必重跑管线
- **升级自动管线的触发条件**:单次手动更新 >1h,或连续两个游戏版本未跟上——届时脚本已在,增量改造即可

**版权口径**:抓取注明来源与日期;不搬运游戏资源;不 vendor 其他仓库的数据文件;数值仅为事实引用。

## 6. 消融分析(每技能马身收益)

- 方法:**leave-one-out 消融**——基准模拟得 T(S),对每个技能 s_i 跑一次去掉它的模拟,收益_i = T(S\{s_i}) − T(S),换算马身 = Δ米/2.5
- 单次模拟毫秒级(约 3600 帧简单积分),全量技能消融 <1s,输入变更实时重算
- UI 同时显示 **Σ单项收益 与 实测总收益**,并解释差异来源(技能交互:回体改变后续发动位置等)——不用增量法(会算错交互)

## 7. UI 设计(v0.1 只做主视图一页)

1. **配置面板**:五维属性(+绿技能前提值)、适性、干劲、跑法、赛场/赛道选择;技能**搜索点选**(按名称/条件/稀有度),不手填数值
2. **主视图**:
   - 赛道条:x = 0→全长,标出弯道(编号)、坡度区间(着色)、阶段分界线、技能发动点(图标+竖线,与曲线联动);近似层技能带角标
   - 双 y 轴曲线:速度(m/s)+ 剩余体力(%),共用距离轴;悬停显示该位置速度/体力/激活技能;**体力归零点醒目标记**
3. **马身收益表**:每技能一行 {技能名, 发动位置, 发动时刻, 马身收益, 时间收益},按收益排序

## 附录 A:关键公式速查(来源与理由记入 docs/formulas.md)

- 体力秒耗:`20.0 × 状态系数 × (v − 基准速度 + 12.0)² / 144.0 × 场地系数`(umamusumeschool)
- 马身换算:`1 马身 = 2.5m`(614tools)
- 起步:出闸初速 3.0 m/s,+24 m/s² 加速至基准速度 85%
- 智力补正:超 1200 部分按档位累计(0–200 每 20 +0.02;200–400 每 20 +0.06;400–800 每 20 +0.01;800–1900 每 100 +0.01);仅对固有/レア 生效
- 焦躁率(仅展示):`(6.5/log10(0.1×智力+1))²%`,每 3 秒 55% 解除,最长 12s
- 校准基准:无技能东京草 2400 ≈ **116.987s**(614tools 公开,自述误差 <0.5s)
